# 基础投稿审核尺度修正

原评分器要求检查题意、输入输出、约束、样例和题解，却未区分基础构思与比赛定稿。实际意见出现把独立字段为空当成缺材料、把非阻塞实现建议当成未通过原因，以及未充分核验自身反驳的问题。

新增审核尺度说明与五个公开合成案例。按语义通读基础与正式字段，基础内容中的样例和约束不要求重复填写。核心明确、思路正确时允许带非阻塞建议通过；关键算法缺口仍要求修改，有合法反例仍可拒绝。难度不能充当通过阈值，也不因未执行测试而声称验证成功。

## 针对性对照

固定五份私有投稿快照与两份公开合成对照；在修改提示词之前跑完基线，再用相同模型配置、同一输入、同一知识点目录和难度参考跑修改后实验。并发四个请求，无 120 秒总时限。两轮整理 JSON；没有改难度映射、阈值或服务认证。

| 结果 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 完整返回 | 7/7 | 7/7 |
| 与独立参考审查结论一致 | 4/7 | 7/7 |
| 核心成立但因定稿/表述问题被要求修改 | 3 | 0 |
| 明确反例被拒绝 | 1/1 | 1/1 |
| 核心构造缺口仍需修改 | 1/1 | 1/1 |

模型使用生产现配的学校接口与 `deepseek-flash`，深度思考开启；运行时间约 9–47 秒/题。私有题面、题解、模型原始回答、实际题号映射与密钥均不入 Git。

参考结论来自本次 AI 独立复核并对照现有人工意见，不冒称全部是人工金标准。这是为解决反馈而选择的小样本、单次前后对照，**不是随机盲测，也不能报告为全库准确率**。部分难度估计有变化，本次没有重新标定 CF 难度准确度。不自动修改已有历史意见或触发全库重审。

后续连接检查发现学校模型别名 `deepseek-flash` 未命中旧代码中只识别 `deepseek-v4-flash/pro` 的显式思考配置。现将该别名纳入同一校验：审阅轮发送 `thinking.type=enabled`、`reasoning_effort=max`，整理轮发送 `disabled` 且不带强度。上表仍是修复别名前的纯提示词对照；不得用它混报显式 max 的效果。别名配置、实际请求与整理轮隔离有 279 项相关单测覆盖。

显式 max 后另跑相同七项，7/7 完整返回、符合 JSON 契约；六项与预先记录的参考一致，一项构造类样本由“需修改”变为“通过”，模型认为可自行补出核心构造，保留此分歧供人工复核，不改写原参考以凑一致率。明确错误的合成反例仍被拒绝。单题约 37 秒至 3427 秒，最慢请求持续流式生成约 57 分钟，未取消或拿未完成结果充数。这说明 max 显著增加延迟，不能假定所有题能在短时间内完成。
