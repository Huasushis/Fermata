# 历史人工审核规范复核

本记录只保存可公开的聚合结论，不包含题目、题号、人员、逐字意见、表格原文、
样本计数或投稿者自报难度。复核对象是两份唯一的历史审核修订；字节相同的副本
先去重，确认原题或重复题只进入原创性核验，不进入命题品味归纳。

## 复核方法

- 总体结论使用历史表中的最终结果。
- 同一题可能同时存在不同审核意见，因此具体证据轴以单条明确通过或否决意见为准，
  不能用最终结果覆盖意见分歧。
- 投稿者自报难度列完全不读取，也不能生成 Fermata 难度真值。
- 正确性检查、题面与题解是核心材料、参考实现可选等规则来自产品与安全要求；
  它们不是从历史意见频率推导出的命题品味标准。

## 安全聚合结论

历史意见不支持把所有维度分成互斥的“通过轴”和“否决轴”。趣味、表达、题解
阐释、比赛适配、公平性、可判定性和自然性都可能在两侧出现，后续规范应使用
中性的证据维度，并分别登记观察到的方向与来源强度。

较稳定的非对称信号是：通过意见中的整体偏好，以及否决意见中的模板化和缺少
新意。整体偏好适合作为人工总体金标准，不适合作为模型自我论证的独立理由；
模型仍须落到具体证据维度。难度和题组位置在两侧都出现，所以只能描述题组角色，
不能单独推出通过或否决。

趣味与选手体验、题面表达、题解阐释、直接比赛适配、知识公平性、可判定性、
自然或优雅、数据与评测准备均有历史依据，但支持较稀疏，不能写成共同的高频
标准。模板化/新意与洞察深度必须拆开；公平性、可判定性与自然性也必须拆开。

实现负担和思维—实现平衡没有足够的历史意见直接支撑。它们仍是用户明确要求的
产品评价维度，但必须标为产品要求，不能继续写成 XML 历史审核重点。选手发现或
反馈过程、教学或练习价值也没有形成可验证的独立历史轴，不应新增为历史标准。

正确性意见没有形成区分通过与否决的品味信号。技术核验仍是一般安全底线，但
技术无错不能自动推出题目值得通过。

## 实验顺序

当前 `historical-rubric-v1` 和对应提示词保持冻结，先用完整、无缺失的开发集运行
修改前基线。任何 HTTP 499、取消、缺收据、跳过、遗留 active 或失败样本都会使
整份报告不完整。

只有基线完整后，才创建新的规范版本和提示词版本作为候选：改成中性证据轴，
拆分被捆绑的维度，区分历史依据与产品要求，并避免把整体偏好当成循环论证。
候选必须使用新标签生成独立报告；最后再用未参与提示词调整的留出集验证。
